# Dataset Specifications (DynoText)

This document outlines the structural, geometric, and metadata specifications for the synthetic DynoText datasets generated by the VQ4M pipeline. The dataset is designed for different usecases: 
1. training and validating robust object detection and tracking models under complex kinematic and lighting conditions.
2. Developing and testing of de-nosing and stabilisation models. 
3. training and validating text recognition models und complex kinematic conditions. 

## 1. Object Classes (Assets)

The dataset currently synthesizes ground-truth data for the following medical assets:
1.  **Syringe**
2.  **PulsOX** (Pulse Oximeter)
3.  **Monitor** (Supports multiple screen asset IDs)
4.  **Lifepak** (Defibrillator)
5.  **Gauge** (Analog dial)

## 2. Dataset Hierarchy & Naming Conventions

To facilitate automated data loading and label parsing, the dataset strictly adheres to a deeply nested, deterministic folder structure. 
`{asset}/{movment}/{image_type}/{video_bg_status}/{view_name}`
 For further detail refer to:  [[Prebuild Scenes (Automated Render Orchestration)#3. Standardized Output Hierarchy|Stadardized Output Hieracrchy]]. 
### Standardized Flat Filenames 
When post-processing scripts (like the bb annotation tool) condense the hierarchy, files are renamed using a flat, hyphenated taxonomy derived from the directory tree:
`[Asset]-[Movement]-[Image_Type]-[Background_Status]-[Viewpoint]-[BoundingBox_Status].mp4`
*(Example: `syr-run-img-wb-cen-box.mp4`)*

## 3. Kinematic Variations 

This dataset provides seven different kinematic variations, which can be sorted into two groups:
* **Static:** `noShake` (Only applied to `/without_video_bg/`).
* **Locomotion IMU Profiles:** `walking`, `running`, `sprinting`, `crouching`, `minimum_shake_walking`, `skipping`.
## 4. View Variations
This dataset provides two to five different variations of camera views.
* **Syringe:** `vertical`, `horizontal` 
* **PulsOX** `far_away`, `close_up`, `normal`.
* **Everything else** `up`, `down`, `left`, `right`, `center`.
## 5. Background Variations
This dataset provides two background options: 
* **Moving Background** a motion typ dependen video from the motion. 
* **Static Background** a epirectangualer image as a skybox. 
## 4. Ground-Truth Annotations

The dataset provides analytical ground-truth bounding boxes derived mathematically from the 3D projection matrix, circumventing the inaccuracies of manual human labeling.



For every rendered sequence, the pipeline outputs two annotation files:

### A. Minimal AABB Tracking (`bb_tracking.csv`)
A lightweight, frame-by-frame tracker containing exactly what is needed to train standard object detectors (e.g., YOLO, Faster R-CNN).
* `frame`: Integer frame index.
* `min_x`, `min_y`, `max_x`, `max_y`: Absolute pixel coordinates of the Axis-Aligned Bounding Box.
* `visible`: Boolean flag indicating if the object is within the camera frustum and unoccluded.

### B. Comprehensive tracking Metadata (`bb_tracking.json`)
A rich, exhaustive log used for complex computer vision tasks (e.g., 6-DoF pose estimation, depth mapping).
* **Camera Data:** Absolute location, quaternion rotation, lens focal length ($mm$), sensor width/height, and principal point shift ($\Delta x, \Delta y$).
* **Object Data:** Absolute center in world space, world normal vectors, and the 3D coordinates of the target plane corners.
* **Projection Data:** Exact 2D pixel coordinates for the Top-Left (`tl`), Top-Right (`tr`), Bottom-Right (`br`), and Bottom-Left (`bl`) corners before AABB circumscription.
